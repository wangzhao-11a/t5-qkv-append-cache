# T5 QKV 拆分与缓存追加算子：社区设计评审草稿

状态：中英文设计文档已提交 [xLLM PR #2604](https://github.com/xLLM-AI/xllm/pull/2604)；算子实现尚未满足全部固定性能门槛。

单 token 解码时，融合输入按全部 Q、全部 K、全部 V 排列。本实现输出独立连续 Q，并向两份历史缓存追加当前 K/V。FP16/BF16 共用 uint16 原样搬运，不执行浮点运算；支持 L=0、奇数维度、原始 NaN 位模式和连续存储偏移视图。

接口包含正式 ACLNN 两阶段 API、独立 C++ 样例、PyTorch `run`、Kernel launch `run_direct` 以及只保存元数据的 `prepare`。详细地址推导、分核、128 KiB 双缓冲、显式 workspace=0、stream 顺序和生命周期策略见 `docs/design.md`。

工程私有安装，不覆盖系统 CANN。当前环境为 Ascend910_9382、CANN 9.1.0、驱动 26.1.1。原题要求驱动 25.5.t6.b001，用户已明确同意采用现有驱动并披露差异；未声称在指定驱动上实测。

最终候选 `c9decf212667337d518e3a1d48dc3e07cd5fef0e` 已完整回收并校验 45 项证据。94 条有效输入/入口逐位检查、84 条非法输入检查、3 类验证器反例、13 条工程检查和 20 条内存记录全部通过；固定性能目标通过 5/10，不能申请“已全部验收通过”。大缓存 FP16/BF16 分别为 94.08875/94.47925 μs，未达到 75/77 μs。

分块、tile/队列深度、L2 读写策略和批量 D2D 均已做对照实验。AIV 与批量 D2D 的大缓存时延均约 94 μs，当前平台实测总读写带宽约 2.854 TB/s，而 75 μs 需要约 3.581 TB/s；这些结果不支持通过继续微调宣称达标。具体失败项和原始五轮数据见 `reports/STATUS.json`、`reports/performance.json` 及交付日志。
