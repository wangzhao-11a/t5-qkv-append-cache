## 新证据

读取既有 916c7d7 的官方 msprof L2 原始 CSV，而非重新跑相同基准。007 后三条任务约 92.8–93.7 us；每条 AIV r0_read_cache_hit=524768、miss=0，r1_read_cache_hit=524767、miss=1。原先 PipeUtilization 中大输入 MTE2=0.77、MTE3=0.748、scalar=0.109。原始 CSV 下载及哈希保存在 artifacts/optimization_20261030/。

这支持优先检查搬运调度和同步，而不是把大量 L2 miss 当成已知瓶颈。数据来自历史版本，不能冒充新候选的计数器结果。

## 对照 1：输出 tile 内聚合

假设：原 Copy 对每个历史/追加片段独立 EnQue/DeQue 和 MTE3 写回；同一 tile 的片段聚合到一个 UB 后，只做一次队列交接及输出写回，可减少 DMA 小事务和同步。

唯一实现变量：大且 32B 对齐的缓存路径，将多个 MTE2 片段放入同一个局部 tile，单次写回完整输出 tile。保留 c9decf2 的 64 KiB×2、48 AIV 交错分核、输入 NORMAL、输出 DISABLE；不引入新 workspace、数据类型转换或第二次 L2 hint。非对齐输入继续使用原始路径。

CPU 地址检查覆盖 35 个公开 shape、120 个随机 shape；增加 UB 片段偏移/长度/源地址的 32B 对齐和容量约束。报告写到独立 artifacts 路径，不覆盖最佳版本报告。

验收仍按构建→扩大 Smoke→完整正确性/工程/内存→固定 50/200/5 性能。任何阶段失败即停止依赖阶段。性能 10/10 全部通过前不标记完成。

构建、Smoke、完整正确性/工程/内存通过，固定性能 0/10。007/017 为 94.1436/93.9224 us。虽然每次调用 K/V 写回从 3070 降到 2050 次，未取得大缓存收益，撤销该运行改动。

证据包 SHA256：a9ba3da354dad516b422ba16c4ca22b234295243e77411b641fd8bdc0942f183。另用官方 msprof Memory 指标对该候选采样，应用三种输入的正确性均通过；大输入最后一条任务 93.182 us，AIV time 90.929 us，UB read/write 28.661/28.662 GB/s。该输出的 L2 bandwidth 字段为 0，不能据此宣称没有 L2 流量，也不能把 per-core/聚合口径不明的计数器直接当整卡峰值。

## 对照 2：核心数缩放

新证据是大量 L2 命中、减少三分之一输出 DMA 次数仍没有可见收益。下一次只把大缓存 AIV 数从 48 降为 24，其他运行代码恢复 c9decf2；小输入核心数不变。

可区分预期：若时延近似翻倍，单核搬运能力/并发是限制；若接近不变，指向已饱和的共享资源；若显著降低，则支持过高并发造成争用。不能在结果前把其中任何一种当成根因。这项对照未出现在已有实验列表中。

## 对照 3：容量约束下部分输出使用 L2

新增直接证据：远端 CANN 配置 Ascend910_9382.ini 的 l2_size=201326592，即 192 MiB。007/017 的历史输入约 128 MiB，加上两份完整输出约 256 MiB，超出 L2 容量。之前全部输出 NORMAL/PERSISTENT 变慢，并未否证部分输出保留在 L2。此前 zero_ 写带宽探针使用默认缓存策略，不能用其数字作为旁路 HBM 写带宽上限。

唯一运行变量：恢复 48 AIV 和 c9decf2 搬运路径；在原本输出旁路的大缓存路径中，只允许 K 输出前缀进入 L2。前缀按完整 tile 截断，预算为 176 MiB 减去全部输入字节数，192 MiB 中预留 16 MiB；输入超过预算时继续全部旁路。007/017 预期约 47.9 MiB 输出进入 L2，剩余约 80.2 MiB 旁路。两种视图分别由原始 GM 指针初始化，避免重复叠加 L2 alias。

这是基于已证实容量的新对照。若输入仍命中且旁路写流量降低，有望改善；若因输出地址轮换等原因超出实际工作集，则可能退化。结果前不把 HBM 瓶颈或预期收益作为已证实事实。

## 对照 10：反向分配缓存，优先保留输出

前九组说明部分输出缓存有收益，但输入逐出对分配历史敏感。新假设是将旁路流量由写改为读：两份输出均 NORMAL，K 历史旁路，V 历史只保留约 47.7 MiB 前缀，剩余部分旁路；输入/输出/packed/query 合计预算 176 MiB。大缓存 HBM 流量仍约 80 MiB，但方向改变。能否受益必须以新数据判断，不能预设 HBM 读取速度。

这与此前全部输入旁路的实验不同：保留部分输入复用，且明确计入输出容量。输出本身超预算时回退到 c9decf2 策略。所有视图从原始指针构造，hint 只应用一次；跨前缀边界的 DMA 进一步切分，地址和逐位复制语义保持不变。小输入、48 核、64 KiB 双缓冲、ACLNN 入口、三个独立新输出和固定 benchmark 不变。

缓存接口语义核对自官方 [SetL2CacheHint 文档](https://www.hiascend.com/document/detail/en/CANNCommunityEdition/850/API/ascendcopapi/atlasascendc_api_07_00033.html)；不引入未合并 PR 或新增依赖。
